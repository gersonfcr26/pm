# Code Review

Full-repo review covering the FastAPI backend, Next.js frontend, AI chat integration, Docker packaging, and repo hygiene. Findings are ordered by severity within each section. Checkboxes are action items.

## Critical

- [x] **`frontend/.local-browsers/` (a full Playwright/Chrome binary, ~395 MB, 308 files) was committed to git.** Fixed: untracked, added to `frontend/.gitignore`, and purged from the entire git history with `git filter-repo` (repo pack dropped from ~426 KB compressed-with-history to ~231 KB, i.e. the binary is fully gone from every commit, not just HEAD). All commit hashes on `main` changed as a result. Since `main` had not yet been pushed to `origin`, no force-push or history reconciliation was needed — `origin` was re-added as a remote and a normal `git push -u origin main` will work. Confirm Playwright's default browser install path (`~/.cache/ms-playwright` or similar) is used going forward instead of a project-local one, so this doesn't recur.
- [x] **`frontend/test-results/` (Playwright trace/error artifacts, including a `trace.zip`) was committed.** Fixed: untracked, added `test-results/` and `playwright-report/` to `frontend/.gitignore`, and purged from git history in the same `git filter-repo` pass as above.

## High priority

- [x] **`AiSidebar.tsx` silently drops any `patch`-mode `boardUpdate`.** Fixed: `patch` mode was never implemented end-to-end, so it was dropped rather than built out. The backend's `AIChatBoardUpdate.mode` is now `Literal["replace"]` and `CHAT_SYSTEM_INSTRUCTIONS` only advertises `replace`, so the model can no longer produce a shape the app can't apply (`backend/app/main.py`, `frontend/src/components/AiSidebar.tsx`).
- [x] **Column rename persists to the backend on every keystroke.** Fixed: `KanbanColumn` now keeps a local `titleDraft` while typing and only calls `onRename` (which flows through to the `PUT /api/board` persist) on blur or Enter, not per keystroke (`frontend/src/components/KanbanColumn.tsx`).
- [x] **Column title can be saved empty.** Fixed: the same blur-commit handler trims the draft and reverts to the last saved title if it's empty, so an empty string is never sent to the backend (`frontend/src/components/KanbanColumn.tsx`).
- [x] **The AI system prompt never describes the board schema or column IDs to the model.** Fixed: `CHAT_SYSTEM_INSTRUCTIONS` now documents the board JSON shape, explains that column ids are stable identifiers and every `cardIds` entry must reference an existing card, and clarifies that a `replace` payload must be the full resulting board (`backend/app/main.py`).
- [ ] **In-memory chat history (`CHAT_HISTORY_BY_USER`) is a per-process global with no eviction beyond a 20-message cap per user.** It's fine for single-user MVP, but note it resets on every restart/redeploy with no persistence and no cleanup for a user who never returns — acceptable now but should be called out in `docs/DB_SCHEMA.md` or `AGENTS.md` as a known limitation if this behavior is intentional (it currently isn't mentioned anywhere).

## Medium priority

- [ ] **Card drag `listeners`/`attributes` are spread across the whole `<article>`, including the "Remove" button (`frontend/src/components/KanbanCard.tsx:29-30`, `42-49`).** `PointerSensor`'s `activationConstraint: { distance: 2 }` (`KanbanBoard.tsx:41-43`) means a slightly-off click on "Remove" can be interpreted as a drag start rather than a click, especially on touch devices. Consider excluding the delete button from the sortable's drag handle area, or verify (with a test) that clicking Remove reliably fires delete rather than a drag.
- [ ] **No CORS configuration in `backend/app/main.py`.** Since the backend serves the built frontend from the same origin in production this is currently harmless, but there's no `CORSMiddleware` and nothing documented about what happens if the frontend is ever served from a different origin (e.g. `next dev` against a separately-running backend during local development). Confirm the intended local dev workflow (is `next dev` expected to talk to the Dockerized backend directly?) and add CORS config if so, or document that frontend dev always proxies through the same-origin build.
- [ ] **`AiSidebar` and `AuthGate` hardcode `MVP_USERNAME = "user"` independently in two files** (`AiSidebar.tsx:38`, `AuthGate.tsx:8`). Since both call backend endpoints with `?username=...`, a single source of truth (e.g. exported from `lib/kanban.ts` or a new `lib/constants.ts`) would prevent drift if the value ever changes.
- [ ] **`save_board` (`PUT /api/board`) does not use `get_or_create_user`'s row before insert atomically with the same transaction guarantees as `get_board`**, but more notably it has no optimistic concurrency check: two concurrent tabs/requests saving the same user's board will silently last-write-wins with no conflict detection. Fine for true single-user MVP, but worth a one-line note in `docs/DB_SCHEMA.md` since the schema is documented as forward-compatible with multiple users.
- [ ] **`frontend/next.config.ts`, `eslint.config.mjs` etc. weren't reviewed for stray defaults** — confirm `next.config.ts` has `output: "export"` (required for the static `out/` directory the backend expects to serve) explicitly set and documented, since the Dockerfile and `main.py`'s `FRONTEND_OUT_DIR` both depend on that build mode.
- [ ] **No `.dockerignore` entry for `frontend/.local-browsers`.** Now that the directory is gitignored rather than tracked, add it to `.dockerignore` too so it can't accidentally bloat the Docker build context if it's ever regenerated locally.

## Low priority / polish

- [ ] **`_provider_from_model` / `resolveProviderTag` duplicate the same `openai/` / `google/` prefix-matching logic in Python and TypeScript** (`backend/app/main.py:257-262`, `frontend/src/components/AiSidebar.tsx:64-75`). Since the backend already returns `provider` in the response, the frontend's fallback branch that re-derives it from `model` is dead code in the normal path — worth simplifying to trust the backend's `provider` field only, per the project's "avoid unnecessary defensive programming" convention in `AGENTS.md`.
- [ ] **`backend/app/main.py` mixes 2-space and inconsistent indentation with the top-level route handlers using 4-space indentation** (compare `health()`/`get_board()` at lines 300-301 vs. the rest of the file at 2-space). Minor, but a formatter (e.g. `ruff format`) run over the backend would keep style consistent.
- [ ] **No `frontend/AGENTS.md`-documented lint/typecheck step is wired into CI** (no CI config exists in the repo at all — no `.github/workflows/`). For an MVP this may be intentional, but if any automated checks are expected before merge, none currently run anywhere except manually via the documented npm/pytest commands.
- [ ] **`docs/PLAN.md` marks all 10 parts complete**, but nothing in the repo re-validates that claim (e.g., no smoke test hits `/api/ai/chat` end-to-end against a live OpenRouter call in CI, understandably, since it requires paid/free-tier keys — but this should be a manual pre-release checklist item rather than assumed from the plan doc alone).

## Notes / things verified as fine

- `.env` is correctly excluded from git via `.gitignore` and is not tracked.
- `BoardModel`'s `validate_references` enforces card-key/id consistency and referential integrity between columns and cards on both read and write paths — solid defensive validation exactly where it matters (user-facing data integrity), consistent with the "no unnecessary defensive programming" principle since this one is load-bearing.
- The AI-chat confirm/reject flow correctly never mutates board state until the user explicitly clicks "Confirm update" (`AiSidebar.tsx:156-166`), matching the required UX from `AGENTS.md`.
- OpenRouter primary→fallback retry on HTTP 429 is implemented consistently for both the connectivity check and the structured chat path, with a clear error when no fallback key is configured.
- Test coverage exists across all major layers (backend API tests, frontend unit tests for `kanban.ts` board logic and `AuthGate`, and a Playwright e2e spec covering drag-and-drop and the AI confirm flow).
- `frontend/.local-browsers/` and `frontend/test-results/` are fully removed from git (working tree and history) as of the `git filter-repo` cleanup; see the Critical section above.
